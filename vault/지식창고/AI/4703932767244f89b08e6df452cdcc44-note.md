**Key take‑aways from the lecture (5 bullets)**  

1. **Language models as probability estimators** – A language model predicts the next token by estimating its conditional probability given all preceding tokens.  The model learns a set of parameters (weights) that maximize the likelihood of the training data.  

2. **Transformer architecture & self‑attention** – GPT stacks many Transformer decoder layers.  Self‑attention lets each token attend to all previous tokens, but future tokens are masked (causal masking) so the model only uses past context.  This is why GPT can generate text but is slightly weaker than BERT, which sees both sides of a token.  

3. **Pre‑training + fine‑tuning workflow** –  
   * **Pre‑training (unsupervised)**: GPT learns from raw text by predicting the next word in a sentence; the “label” is the actual next word, so no external annotations are needed.  
   * **Fine‑tuning (supervised)**: The same architecture is used to predict task‑specific labels (e.g., sentiment, entailment, classification) from input text.  

4. **Evolution of GPT** –  
   * **GPT‑1**: Baseline transformer decoder with ~1 B parameters, trained on a large web‑crawled corpus.  
   * **GPT‑2**: Same architecture, but trained on a much larger, higher‑quality web‑text dataset.  
   * **GPT‑3**: Same architecture, but dramatically larger (tens of billions of parameters) and higher‑dimensional hidden states, yielding better performance but also higher compute cost.  
   * **GPT‑4** (upcoming) aims to balance size and efficiency, possibly using distributed training and more specialized data (e.g., dialogue).  

5. **Practical implications** – GPT‑2/3’s huge parameter counts make them hard to run on a single server, driving research into efficient, smaller‑scale models (e.g., DialoGPT) and distributed inference.  Fine‑tuning these models on domain‑specific data (chat logs, sentiment labels, etc.) can produce powerful, task‑specific applications such as chatbots, classification, and natural‑language inference.
