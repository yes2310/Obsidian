**Lecture Summary – GPT (Generative Pre‑trained Transformer)**  

| Topic | Key Points |
|-------|------------|
| **Language Modeling Basics** | • Goal: predict next token \(w_i\) given previous tokens \(w_1,\dots,w_{i-1}\). <br>• Uses conditional probability \(P(w_i|w_1,\dots,w_{i-1})\). <br>• Parameters \(\theta\) are learned weights that maximize likelihood over a corpus. |
| **Vector Representation** | • Tokens → token embeddings. <br>• Add segment and position embeddings. <br>• Resulting vectors are fed into the model. |
| **Transformer Architecture** | • Self‑attention (scaled dot‑product). <br>• Multi‑head attention allows each token to attend to all others. <br>• GPT uses only the decoder side (masked self‑attention). |
| **BERT vs GPT** | • BERT: encoder‑only, uses masked language modeling (MLM). <br>• GPT: decoder‑only, uses causal language modeling (predict next token). <br>• GPT can’t look ahead, so it may under‑perform on tasks that benefit from bidirectional context. |
| **Training Phases** | • **Pre‑training** (unsupervised): learn language structure from raw text. <br>• **Fine‑tuning** (supervised): adapt to a specific downstream task with labeled data. |
| **Unsupervised Pre‑training** | • Even without explicit labels, the model can generate “pseudo‑labels” (e.g., masked tokens in BERT, next‑token predictions in GPT). <br>• Loss is computed against these generated targets, enabling back‑propagation. |
| **Fine‑tuning Tasks** | • Classification, sentiment analysis, natural language inference, similarity, multiple‑choice QA, etc. <br>• Input format: `[CLS] sentence1 [SEP] sentence2 [SEP]` → linear layer → logits → softmax. |
| **GPT Versions** | • **GPT‑1**: 1‑B parameters, trained on 8M web pages. <br>• **GPT‑2**: same architecture, but trained on a massive, high‑quality web‑scraped corpus (≈40B tokens). <br>• **GPT‑3**: dramatically larger (≈175B parameters), deeper, higher‑dimensional embeddings. <br>• **GPT‑4**: upcoming, expected to be more efficient (smaller parameter count, better scaling). |
| **DialoGPT** | • Fine‑tuned GPT‑2 on conversational data (≈200k chat‑style sentences). <br>• Achieves higher accuracy on dialogue tasks (≈0.87 on 200k‑sentence fine‑tune). <br>• Useful for building chatbots with minimal fine‑tuning. |
| **Practical Considerations** | • GPT‑2/3 models are huge; running them on a single GPU is infeasible. <br>• Requires distributed inference (model parallelism, sharding). <br>• Fine‑tuning smaller models can yield competitive performance with lower cost. |

**Take‑away:** GPT is a powerful, general‑purpose language model that learns to predict the next token from raw text. Its success stems from massive pre‑training data and ever‑larger model sizes. Fine‑tuning on a small labeled set allows it to excel across a wide range of NLP tasks, from classification to dialogue generation.
